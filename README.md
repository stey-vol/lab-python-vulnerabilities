# Лабораторная работа: уязвимости веб-приложения (OWASP Top 10)

Учебный стенд на Python. Веб-приложение содержит **две намеренные уязвимости**,
скрипт показывает их эксплуатацию, а `patch.diff` их устраняет.

> ⚠️ Приложение специально сделано уязвимым. Запускать **только локально**, в интернет не выкладывать.
> Весь код написан на **стандартной библиотеке Python** — ничего устанавливать не нужно.

## Файлы

| Файл | Что это |
|------|---------|
| `app.py` | Веб-приложение с двумя уязвимостями (форма входа + гостевая книга) |
| `exploit.py` | Скрипт, который атакует приложение (часть 2) |
| `patch.diff` | Исправление обеих уязвимостей в формате diff (часть 3) |
| `app_fixed.py` | Готовая исправленная версия (результат применения патча — для наглядности) |

## Уязвимости

### 1. SQL-инъекция — OWASP A03:2021 (Injection)
В форме входа логин и пароль напрямую вставляются в текст SQL-запроса:
```python
query = "SELECT username FROM users WHERE username = '%s' AND password = '%s'" % (username, password)
```
Если ввести в поле логина `admin' OR '1'='1`, условие становится всегда истинным,
и вход выполняется **без знания пароля**.

### 2. XSS (межсайтовый скриптинг) — OWASP A03:2021 (Injection)
Сообщения из гостевой книги выводятся в HTML **без экранирования**. Если отправить
сообщение `<script>alert('XSS')</script>`, то у каждого, кто откроет страницу,
в браузере выполнится чужой JavaScript.

## Как запустить

### Часть 1 — запустить уязвимый сайт
В терминале (в этой папке):
```bash
python3 app.py
```
Открой в браузере http://127.0.0.1:8000

Попробуй вручную:
- **SQL-инъекция:** в поле «Логин» введи `admin' OR '1'='1`, пароль любой → пустит внутрь.
- **XSS:** в гостевую книгу отправь сообщение `<script>alert('XSS')</script>` → при обновлении страницы выскочит окно alert.

### Часть 2 — запустить атаку скриптом
Оставь `app.py` работать, открой **второе окно терминала** и запусти:
```bash
python3 exploit.py
```
Скрипт сам проведёт обе атаки и покажет результат в консоли.

### Часть 3 — применить исправление
Останови сервер (`Ctrl + C`) и применить патч:
```bash
patch app.py < patch.diff
```
После этого снова запусти `python3 app.py` и `python3 exploit.py` —
обе атаки больше **не проходят**:
- вход по `admin' OR '1'='1` → «Неверный логин или пароль»;
- `<script>` в гостевой книге выводится как текст (`&lt;script&gt;`), а не выполняется.

> Если не хочешь менять `app.py`, просто запусти уже исправленную версию: `python3 app_fixed.py`.

## Как исправлены уязвимости (суть патча)

1. **SQL-инъекция** → параметризованный запрос: данные передаются отдельно от SQL-кода
   через `?`, и база не воспринимает их как команды.
2. **XSS** → экранирование вывода через `html.escape()`: спецсимволы `< > & "`
   превращаются в безопасные `&lt; &gt; &amp; &quot;`.
